Talking to R: vectors, indexing & matrices

Before we can model anything, we need to speak R fluently. 1.1

How to work in R

R is a free programming language made for statistics. RStudio is the program you open to write R comfortably. RStudio has four panes: the script (top-left, where you write and save code), the console (bottom-left, where R prints results), the environment (top-right, a list of everything you have stored) and plots/help (bottom-right).

  1. Write code in a script file (.R) so you can save and re-run it — like Lec 1.R.
  2. Put the cursor on a line and press Ctrl + Enter. RStudio sends that line to the console and R runs it.
  3. Anything after a # is a comment: R ignores it. Comments are notes for humans.
  4. R answers in the console. A line like [1] 5 means "here is the result, and the first value shown is element number 1".
in plain words

Think of R as a very fast, very literal calculator that can remember things. You tell it something, it answers immediately. Every lecture page here also has a live R console — the blue R> button bottom-right. Any code box with a ▶ run button can be sent straight to it.

1.3

Storing values: variables and vectors

To remember a value, give it a name using the assignment arrow <- (read it as "gets"). x <- 5 means "x gets 5". You can also use =, and the script uses both — they do the same job here.

Data almost never comes as a single number, so R's basic building block is the vector: an ordered row of values of the same type. You build one with c(), which stands for combine.

x <- c(1,3,4,3) ;  x  ;x+6
class(x)

[1] 1 3 4 3
[1]  7  9 10  9
[1] "numeric"
  • The semicolon ; lets you put several commands on one line. Here: store x, show x, then show x + 6.
  • x + 6 adds 6 to every element at once. This is called vectorised arithmetic — no loop needed. It is one of R's superpowers.
  • class(x) tells you what type of object x is. "numeric" means numbers with decimals allowed.

  • The numbers in square brackets at the start of each printed line are position labels, not data. [22] means "the first number on this line is element 22" (which is 32). They help you count in long outputs.

  • x1 = x makes a copy called x1.
Remember

  • Wrapping an assignment in parentheses (x <- …) stores and prints in one go.
  • Names may contain dots: x.mean is just one name. mean(x) = (1+3+4+3)/4 = 2.75.
  • sum = x + y creates a variable called sum holding (3, 6, 9, 4). But sum(x, y) still calls the function sum and adds up everything: 1+3+4+3+2+3+5+1 = 22. R is smart enough to look for a function when it sees brackets — but it is confusing for humans.
  • length(x) = number of elements (4). dim(x) is NULL because a plain vector has no rows/columns — only matrices and data frames have dimensions.
Common mistake

Avoid naming your variables after built-in functions (sum, mean, c, data, t…). It works, but it makes code hard to read and can cause strange bugs later. Prefer names like total or xy_sum.

1.4

Missing values: NA

Real data has holes — a person skipped a survey question, a sensor broke. R marks a missing value with NA ("Not Available"). This matters a lot: in Lecture 4 a whole lecture is about missing data in regression.

v1 <- c(1, 2, 3, NA)
v1[4]
v1[4] =10
mean(v1)
v1 <- c(1, 2, 3, NA)
mean(v1)
class(v1)
mean(v1, na.rm =  TRUE )

[1] NA
[1] 4
[1] NA
[1] "numeric"
[1] 2

Why does mean(v1) give NA? Because R refuses to guess. If one value is unknown, the average is unknown too. You have to say explicitly "ignore the missing ones" with the argument na.rm = TRUE (NA remove). Then the mean is (1+2+3)/3 = 2.

Note

Picking elements: indexing with [ ]

Square brackets after a vector mean "give me some of the elements". What you put inside decides which ones. There are three ways:

positive numbers

"take these positions"

negative numbers

"everything except"

v[-3], v[c(-2,-3)], v[-1]

TRUE / FALSE

"keep where TRUE"

v[c(T,T,F,F,T,F)], v[v > 12]

Common mistakes
  • v[1,5] is wrong for a vector — the comma means "row, column" and only works on matrices. To get two elements use v[c(1,5)].

1.7

Arithmetic between vectors — and recycling

When you add two vectors, R works element by element: first with first, second with second, and so on.

v1 <- c(1,2,3,5,1,2)
v2 <- c(4,5,6)
v1 + v2
v1 - v2
v1 * v2

[1] 5 7 9 9 6 8
[1] -3 -3 -3  1 -4 -4
[1]  4 10 18 20  5 12

But wait — v1 has 6 elements and v2 only 3! R handles this by recycling: it repeats the shorter vector from the start until it is long enough. So v2 behaves like (4, 5, 6, 4, 5, 6). Since 6 is a multiple of 3, this works silently.

v1 <- c(1, 2, 3, 4, 5)
v2 <- c(1, 2)
v1 + v2

[1] 2 4 4 6 6
Warning message:
In v1 + v2 :
  longer object length is not a multiple of shorter object length

Here 5 is not a multiple of 2, so v2 becomes (1, 2, 1, 2, 1) and R still gives an answer — but warns you, because this is usually a mistake.

1.8

Matrices: data in rows and columns

A matrix is a vector arranged into a rectangle of rows and columns. All entries must be the same type (all numbers, for example). You make one with matrix(data, nrow, ncol, byrow).

M <- matrix( c(1:6), nrow = 2, ncol = 3, byrow = TRUE)
print(M)
M <- matrix( c(1:6), nrow = 2, ncol = 3, byrow = FALSE)
M <- matrix( c(1:6), nrow = 2, ncol = 3)
print(M)

     [,1] [,2] [,3]
[1,]    1    2    3
[2,]    4    5    6

     [,1] [,2] [,3]
[1,]    1    3    5
[2,]    2    4    6
  • byrow = TRUE: fill the first row left-to-right, then the second row…
  • byrow = FALSE (the default, so you can leave it out): fill the first column top-to-bottom, then the second column…
  • Labels like [1,] mean "row 1, all columns" and [,2] means "all rows, column 2". This is exactly the syntax you use to index (section 1.9).

1.10

Matrix arithmetic: element-wise vs matrix product

The ordinary operators + - * / work element by element, exactly like with vectors: the cell in row i, column j of the result only uses the cells in row i, column j of the two inputs.

M1 <- matrix(c(10:21), nrow = 4, byrow = TRUE)
M2 <- matrix(c(0:11),  nrow = 4, byrow = TRUE)
M1 + M2
M1 * M2
M1 / M2

[2,] 4.333333  3.500000 3.000000
[3,] 2.666667  2.428571 2.250000

Look at the top-left: 10 / 0 = Inf (infinity). R does not crash when you divide by zero — it returns Inf (or NaN, "not a number", for 0/0).

The matrix product %*%

The "real" matrix multiplication from linear algebra is written %*%. To get cell (i, j) of A %*% B you take row i of A and column j of B, multiply them pair by pair, and add up. That only works if A has as many columns as B has rows (we say they are conformable).

$$ (AB)_{ij} = \sum_{k} A_{ik}\,B_{kj} \qquad\text{e.g. } (AA)_{11} = 0\cdot0 + 1\cdot3 + 2\cdot6 = 15 $$

  • t() = transpose: rows become columns. t(a) turns the vector into a 1×3 row.
  • a %*% a = 1·1 + 2·2 + 3·3 = 14, the dot product. R quietly treats the first a as a row and the second as a column.

  • There is only one kind of addition: A + A is always element-wise.

1.12

Why all this matrix stuff? A sneak peek at regression

It can feel like Lecture 1 is pure programming. It isn't: every function you just learned is exactly what R uses internally to fit a regression line. In Lecture 3 you will see the Ordinary Least Squares formula. In matrix form it is:

$$ \hat{\boldsymbol\beta} = (X^\top X)^{-1} X^\top y $$X = data matrix with a column of 1s (for the intercept), y = response vector

Read it with Lecture 1 eyes: cbind(1, x) builds X (a column of ones glued to the data), t() transposes, %*% multiplies, and solve() inverts. Here it is on the study-hours data from Lecture 3:

hours  <- c(2, 4, 6, 8, 10, 3, 5, 7, 9, 11)
scores <- c(60, 70, 80, 85, 90, 65, 75, 82, 88, 92)
X <- cbind(1, hours)                       # 10 x 2 design matrix
solve(t(X) %*% X) %*% t(X) %*% scores      # (X'X)^-1 X'y

           [,1]
      55.654545
hours  3.545455

Those two numbers — intercept 55.65 and slope 3.55 — are exactly what lm(scores ~ hours) reports in Lecture 3. You have just fitted a regression line with nothing but Lecture 1!

Lecture 1 quiz

What does v[-3] return if v <- 10:15?
A negative index means "everything except that position". Position 3 holds 12, so it is dropped.
mean(c(4, NA, 8)) returns…
One unknown value makes the mean unknown. You need mean(c(4, NA, 8), na.rm = TRUE) to get 6.
What is c(1, 2, 3, 4) + c(10, 20)?
Recycling: (10, 20) is repeated to (10, 20, 10, 20). No warning, because 4 is a multiple of 2.
matrix(1:6, nrow = 2) — what is its first row?
The default is byrow = FALSE, so R fills column by column: column 1 = (1, 2), column 2 = (3, 4), column 3 = (5, 6). Row 1 is therefore 1 3 5.
For M <- matrix(10:21, nrow = 4, byrow = TRUE), what does M[,2] give?
Empty before the comma = all rows; 2 after the comma = column 2.
A is 3×3. Which of these fails?
For %*% the number of columns of the left matrix (3) must equal the number of rows of the right one. A 1×3 matrix has only 1 row → "non-conformable arguments". A plain vector of length 3 is treated as a 3×1 column, so the last option works.
What does solve(M) compute?
solve(M) returns M⁻¹, so that solve(M) %*% M is the identity matrix. det() gives the determinant and t() the transpose.
After x <- 11:100, what is x[69]?
x starts at 11, so element k equals k + 10. Element 69 → 79.
★

Summary

  • <- stores a value; c() builds a vector; a:b makes a sequence.
  • Arithmetic on vectors is element-wise; a shorter vector is recycled (warning if lengths don't fit).
  • NA = missing. Most summaries return NA unless you add na.rm = TRUE.
  • Index vectors with v[ ]: positive = take, negative = drop, logical = keep where TRUE.
  • matrix(data, nrow, ncol, byrow) — default fills by column. Index with M[row, col]; empty = all.
  • * is element-wise, %*% is the matrix product, t() transposes, solve() inverts, det() gives the determinant.
  • These tools are the engine of regression: \(\hat\beta = (X^\top X)^{-1}X^\top y\).
